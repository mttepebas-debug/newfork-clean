## In scope
- Bugün: `chain()` (`scripts/guard.mjs:80-94`) heredoc/here-string gövdesini satır bazında atıp (`dropBodies`) kalanı tırnağa bakmadan
  `&&`, `||`, `;`, `|`, satır sonunda bölüyor. Gerçek örnek (PARALEL-1, 2026-10-07): `node -e 's=s.replace("a.mjs","b.mjs && turbo test");'`
  → parça `turbo test"` → ağır koşu "test".
- Yeni: tek geçişli tarayıcı; ayırıcı yalnız tırnak dışında sayılır. Kabuğa göre (`tool_name`):
  - Bash: `'…'` (kaçış yok), `"…"` (`\"`, `\\`, `\$`, `` \` `` kaçışı), `$'…'` (`\'`, `\\`), tırnak dışında `\x` tek karakter.
  - PowerShell: `'…'` (`''` kaçışı), `"…"` (`` `" `` ve `""` kaçışı), tırnak dışında `` `x ``; ters bölü sıradan karakter (`C:\x\`).
  - İkisinde: çift tırnak içindeki `$( … )` iç içe okunur (içindeki tırnak ve heredoc da), `)`'si bulunana kadar.
  - Heredoc (`<<EOF`, `<<-EOF`, `<<'EOF'`, `<<"EOF"`, `<<\EOF`; `<<<` değil): gövde, satır sonundan bitiş satırına kadar atılır;
    bitiş satırı yoksa gövde atılmaz (bugünkü kural: komut gizlenmez).
  - Here-string (`@'` / `@"` satır sonunda, bitiş `'@` / `"@` satır başında): gövde atılır, bitişten sonrası komut. Bugünkü testler
    bunu Bash aracıyla da sınıyor, ikisinde de çalışır.
- **Ek 1:** satır devamı (Bash `\`+satır sonu, PowerShell `` ` ``+satır sonu) ayırıcı değil. Bugün `git push \⏎ origin HEAD:main`
  iki parçaya bölünüyor ve main push'u görülmüyor.
- **Ek 2:** `#` yorumu (kelime başında, tırnak dışında) satır sonuna kadar metin. Bugün `echo x # && pnpm test` ağır koşu sayılıyor.
- **Ek 3 (inceleme bulgusu, yolda):** başka kabuğa sarılmış komut (`bash -c "…"`, `sh -c`, `pwsh [-NoProfile] -Command "…"`,
  `cmd /c "…"`) o kabuğun komutları olarak okunur. Neden: eski bölücü, tırnak içindeki ayırıcı yüzünden
  `bash -c "cd x && git push origin HEAD:main"` içindeki main push'unu tesadüfen yakalıyordu; tırnağa saygılı bölücü bunu kaybediyordu
  (kancanın tek fail-closed kontrolü). Önündeki `NF_OVERRIDE=` scriptin her komutuna geçer. `pwsh -EncodedCommand` okunmaz.
