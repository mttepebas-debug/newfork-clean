## 4. Asama B: Veri ve contract degisimi

Yeni kavramsal contract mevcut API kaliplarina yerlestirilir; fiziksel isimler migration bagimlilik incelemesinde belirlenir. Kamu davranisi su olmalidir:

| Arayuz | Gerekli sozlesme |
| --- | --- |
| Calisan haftasi oku/kaydet | Revision, beyan edilmis mi, kayitli giris modu, yedi gun, unavailable type kimlikleri VEYA tek aralik VEYA All day; server aktoru kendisi belirler |
| Manager hatirlatmasi oku/kaydet | Ayri revision, enabled, ayni hafta yapisi, gun notlari; yalnizca yetkili manager |
| Availability ayarlari | input mode, warning policy, onboarding required; revision, owner/admin yazma |
| Degerlendirme | Hedef calisan/lokasyon/is/tarih/gercek aralik/atama baglami; kaynakli kesisimler, kontrol durumu, fingerprint ve ilgili kabul kaniti |
| Kaydetme oncesi ustlenme kontrolu | Yeni haftaya gore etkilenen bekleyen talep kimlikleri/revision'lari; her birinde koru/iptal karari |
| Availability kaydi sonucu | Yeni revision, uygulanan talep kararlari, yarisi kazanip kesinlesen talepler ve calisan sorumluluk mesaji |

- Unavailable kurallarini dogrudan sakla; yeni public editor contract'inda available araliklarinin tumleyenini gostermek zorunda kalma.
- Yedi gun icin tek temsili dogrula; UI modu degisse bile eski kayit saved input mode ile okunabilir kalir. Eski katalog girdileri icin ad/default saat fallback'i korunur.
- Calisan ve manager verileri fiziksel veya yetkilendirme olarak ayri alanlarda; employee cevaplari, realtime ve paylasimlarda manager notu/kurali sizmaz.
- Audit gecmisi yetkili manager'a; actor, once/sonra, zaman ve revision. Calisan tarihli tercih surumlerini yonetmez ama sistem audit ve yayinlanmis degerlendirme kanitini korur.
- Bekleyen taleplerin kararlari ve availability kaydi server transaction'inda tekrar dogrulanir. Manager onayi once kesinlestiyse talep iptal edilmez; belirtilen kismi sonuc sozlesmesi doner. Teknik hatada yarim kayit olmaz.
- Iki yoneticinin kaydi optimistic revision kontrolu kullanir. Notification olayi transaction/outbox'a eklenir; ayni komut tekrari cift bildirim yaratmaz.
- RLS/API testleri: employee kendi tercihine yazabilir, manager baska employee beyanini bu editorle degistiremez; ortak hatirlatma izinleri spec'e uyar; kendi employee kaydina manager rolu istisnasi desteklenir.
