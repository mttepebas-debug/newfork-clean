The web app's `dark:` Tailwind variants are wired to the wrong signal, app-wide.

Evidence gathered 2026-07-27 by measuring the running app in the browser:
- `apps/web/tailwind.config.ts` has NO `darkMode` key, so Tailwind uses its default `media` strategy. Every `dark:` utility compiles to `@media (prefers-color-scheme: dark)`.
- The app has no dark mode toggle and no `.dark` class. Theming is 63 `[data-theme="..."]` blocks of CSS variables in `apps/web/src/index.css` (default, refined, warm, latte, moss, forest, crimson, sapphire, midnight, calcite, walnut, ocean, bordeaux, graphite, sage, estate, harbor, vineyard, espresso, fjord, ...). Some of those themes are dark; the `dark:` variant knows nothing about which one is active.
- Net effect: on a LIGHT theme viewed from an OS set to dark mode, `dark:` utilities fire and paint dark colours onto light surfaces. On a DARK theme viewed from an OS set to light mode, they never fire and dark-intended styling is missing. Verified live: `data-theme="sapphire"` (`--card: 0 0% 100%`, white) with `matchMedia('(prefers-color-scheme: dark)').matches === true`, and `dark:bg-red-950/20` computed to `rgba(69,10,10,0.2)` over the white card.

This was already fixed inside the employee drawer (commit 01b15add) by replacing `dark:` variants with translucent palette tints such as `bg-red-500/10` / `border-red-400/45`, which composite correctly over any theme surface.

Remaining known sites with the same defect:
- `packages/ui/src/components/badge.tsx` — `badgeToneClass` (amber/red/blue/violet/emerald/slate), every tone has a `dark:` half. NOTE: this constant carries an explicit "FOUNDER DECISION 2026-07-26" comment about the light `-50` tint treatment, and a contrast test at `badge.contrast.test.ts` that measures both light and dark pairs. Do not change the visual decision — only change the MECHANISM so the dark half activates on dark themes instead of on OS preference.
- `[GİZLİ].tsx` — `DocumentStatusBadge` tones and `UploadedMeta` expiry text.
- Sweep the rest of `apps/web/src` and `packages/ui/src` for `dark:` — there are likely more.

Two candidate fixes, pick one and explain the tradeoff to the founder before doing the sweep:
(a) Set `darkMode: ["selector", '[data-theme="midnight"], [data-theme="graphite"], ...']` in `apps/web/tailwind.config.ts` listing every dark theme, so existing `dark:` utilities keep working and start keying off the active theme. Needs an accurate list of which of the 63 themes are dark, and `packages/ui` is compiled by the same config via the content glob so it inherits the fix.
(b) Drop `dark:` entirely and express tone with translucent palette tints (the drawer's approach), which needs no per-theme knowledge at all.

Add a regression guard either way — e.g. a lint rule or a test that fails when a `dark:` class appears while `darkMode` is unset.
