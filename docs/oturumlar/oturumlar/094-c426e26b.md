## Two traps that made the report lie

**Harvest timestamps are not durations.** `completed_at − dispatched_at` on a row whose own detail says `Total time: 25000.595 ms` records as **19ms**. Every success looks like 25-40ms regardless. I discarded that signal mid-investigation.

**The monitor's blind spot — the reason item 3 read as "not scheduled".** A trigger job that never reaches `trigger_endpoint` queues no pg_net request, lands no dispatch row, so the harvest has nothing. `cron-health.ts` read `cron.job_run_details` only for the four SQL-command jobs → zero successes AND zero failures, indistinguishable from unscheduled. Added a third union arm, **failures only, never successes** (a pg_cron `succeeded` means the command returned, not that the endpoint answered). Verified on real DB:
